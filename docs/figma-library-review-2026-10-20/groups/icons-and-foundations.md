# Icons and foundations — current evidence, 2026-10-20

The component-file review is supplemented by the linked Icon Library's **System** page (`Y7VyYvcCvXjG1pgeXicozZ`, `0:1`). It has 589 component masters: 291 active 24px masters, 291 active 20px masters and 7 deprecated masters. All names, vector path data, vector bounds, transforms, fills and strokes were extracted. This is not a full raster/path-normalized equality test. Third Party, File Type, Country Flags and Brand pages are outside this component-library comparison.

The local `Icon/iconPaths.ts` has 300 entries. Normalizing camelCase to kebab-case finds 285 direct name matches plus 9 documented alias matches. These are local-entry counts, not distinct Figma glyph counts or a fidelity percentage. Four active medium glyphs have no matched Icon entry: `AI_irisInverse` (`4469:31`), `documentAnalyze` (`7426:71`), `documentSplit` (`7426:73`), `folderCopy` (`7426:75`). `IrisIconInverse` separately represents the first; the other three remain capability gaps if a key screen requires them. Six local entries lack a direct medium counterpart under this bounded mapping (`sliders-horizontal`, `ai-iris-filled`, `arrow-nested-small`, `boolean`, `line`, `presentation`); alias/extension status is explicit rather than counted as wrong geometry.

`Icon` renders one monochrome path with a default 24px viewBox and scales that path to 16px for small. Figma has independent small-master geometry in 20px containers. `arrow-nested-small` is the sole local custom 16px viewBox. Small glyph geometry is therefore not guaranteed by matching the medium name. The old single-bar `process-spinner` concern is closed: both current source and current Figma have multiple segments, but exact outline equality was not established.

## AI and Iris renderers

Four current design contexts/screenshots were visually inspected: [Iris](https://www.figma.com/design/Y7VyYvcCvXjG1pgeXicozZ?node-id=2800-343), [inverse Iris](https://www.figma.com/design/Y7VyYvcCvXjG1pgeXicozZ?node-id=4469-31), [spark outline](https://www.figma.com/design/Y7VyYvcCvXjG1pgeXicozZ?node-id=2800-345), [spark filled](https://www.figma.com/design/Y7VyYvcCvXjG1pgeXicozZ?node-id=2800-347). Both sizes of all eight AI masters have geometry and ancestor-visibility records.

- **AIIcon ignores `name`.** It always draws the filled 12px spark path, so its advertised Iris and outline-spark choices cannot render their actual geometry. Current App uses the filled-spark choice; the latent Iris/outline choices must not be called visually verified. Figma's spark occupies a 12px glyph inside its 24px/20px container, while AIIcon's viewBox is the glyph itself; size props do not imply equal optical size.
- **Generic Icon's AI paths are separate geometry.** Local `ai-iris` is a monochrome four-point diamond shape; current Iris has multiple petals and a gradient center. Local `ai-spark` is an 18px outlined star in a 24px viewBox; current Figma spark is approximately 12px. Name presence does not establish equality. Existing ThinkingSteps uses generic `ai-spark`, so this is relevant to representative AI states.
- **IrisIcon is also distinct.** It renders four pale petals plus a gradient center (five paths). Current Iris masters expose nine visible vector descendants, including eight pale petal paths. Its viewBox/optical sizing also differs. Treat the local renderer as a separate implementation needing selected-screen comparison, not an exact match inferred from its source comment.
- **IrisIconInverse has the expected five-part structure.** Its 20px viewBox, four gradient petal coordinates and white center follow the current small-master structure to rounded source coordinates. Raster equivalence remains unverified. Its SVG IDs are fixed (`irisInvA` etc.), as are standard Iris's `irisGradient`; repeated-instance ID behavior needs browser verification before an upstream change is chosen.

Current component-file metadata cannot validate AIBadge's old `19467:181071` source citation: that node was not found. Current Alert template target `123:919` also returned invalid selection. This is an unresolved reference, not evidence that Alert/AIBadge lack runtime implementations. No new Figma mapping was written.

## Tokens and typography

All **855 local variables** were extracted and aliases resolved without a missing reference: Ink 468, `_Utilities` 40, deprecated collection 347. Ink has Standard, Inverse, Standard (Touch), Inverse (Touch). These are mode values, not four separately named token families. There are 28 text styles, 4 paint styles and 10 effect styles. The July 504-variable/14-effect counts are historical.

The reproducible [comparison script](../compare-tokens.py) compares explicit Standard-mode name mappings only. Of Ink's 468 variables it records 357 equal values, 11 different values, 78 without an explicit mapping and 22 deprecated/nonsemantic exclusions. No value-only fuzzy matching is used, and the result is not a fidelity score. The 11 differences include success/warning text colors, focus inset, combo-divider colors, toggle selected/hover lanes and popover-close opacity. Semantic/consumer relevance must be reviewed before treating these as fixes. Focus decisions and code-only extensions are not automatically regressions.

Current `elevationGlass` blur is 16px; local `--ink-elevation-glass` is 8px. This remains a current value difference, consequential when a key screen uses the glass surface. The component file still has only the four named two-stop gradient paint styles; AI glyphs themselves do contain their own gradient paints. Lack of a shared AI paint-style name does not mean the brand gradient is absent from Figma.

Twenty-seven text styles have matching named size/line-height tokens; `[PR] fontNumeric` has no dedicated pair. This validates token values rather than every component's application. Generic `Text` always uses a 1.5 line-height and optional weight, while Figma styles vary by semantic role; generic `Heading` maps semantic levels to a different size/weight ramp and has no displayLevel prop. Use PageHeader and the documented token-based hierarchy for key screens. Do not infer type parity from the font-family name or token existence alone.
